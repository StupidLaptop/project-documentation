# Handoff editing instructions

Read the root `AGENTS.md` first. Use `templates/feature-handoff.md` to bound each feature. Include outcome, scope, requirement IDs, hard and soft prerequisites, rules, authorisation, decisions, open gates, negative cases, acceptance scenarios, evidence, and sources. Do not promote a handoff while an unanswered question could materially change its outcome. Identify which open questions can safely wait for implementation planning. Record approval by name or role and date. Keep implementation-local tasks and code details out of the approved product boundary unless the project has explicitly selected a technical constraint.
