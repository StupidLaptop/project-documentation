# Feature handoffs

Feature handoffs define the **what**, the boundaries, and the evidence needed for acceptance. A delivery team's implementation plan defines the **how**. Keep those responsibilities distinct.

| Folder | Meaning |
| --- | --- |
| [drafted/](drafted/README.md) | Being refined or held at a blocking question |
| [approved/](approved/README.md) | Suitable bounded input for delivery planning |
| [implemented/](implemented/README.md) | Delivered and reviewed, with deviations and residual work recorded |
| [templates/](templates/README.md) | Handoff, plan, and review examples |

Use a stable feature ID across states. Move or copy a record into a later state only with its status and links updated. Approval of a handoff is not implementation acceptance or deployment evidence.
