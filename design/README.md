# Design workspace

Use this area when the project has interfaces or other designed experiences. Reference material and prototypes are evidence; only reviewed contracts become delivery inputs.

| Folder | Purpose |
| --- | --- |
| [principles/](principles/README.md) | Reviewed experience and accessibility principles |
| [system/](system/README.md) | Shared tokens, components, content and layout contracts |
| [patterns/](patterns/README.md) | Reusable interaction patterns proven by features |
| [reference/](reference/README.md) | Existing products, mockups, brand material, and research as evidence |
| [proposals/](proposals/README.md) | Feature-specific options awaiting review |
| [approved/](approved/README.md) | Versioned, approved design contracts linked from handoffs |
| [superseded/](superseded/README.md) | Replaced approved designs kept for historical context |
| [templates/](templates/README.md) | Proposal, review, and contract starting points |

Record loading, empty, error, validation, forbidden, stale-data, responsive, keyboard, focus, and assistive-technology behaviour when applicable. A design that exposes a product question links it to the inbox; it does not silently answer it.
