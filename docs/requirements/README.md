# Requirements

Keep approved obligations here, grouped by coherent capability or domain. Give each requirement one stable ID and one primary home; link across domains instead of duplicating wording. For each requirement, record the source, status, rationale where useful, acceptance meaning, and any accepted decision or change that modifies it.

Use [the requirement template](../templates/requirement.md) as a starting point. A proposal belongs in the inbox until approved. If a source contains a requirement whose meaning is disputed, preserve the original wording and link an open question rather than silently interpreting it.
