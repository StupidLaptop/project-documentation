# Canonical documentation instructions

Read the root `AGENTS.md` first. Preserve stable IDs and link requirements to their source or accepted change. Keep original inputs under `source/` unchanged. Split maintained files by coherent domain or capability. When a rule changes, update its primary file and the traceability record, then inspect dependent workflow, schema, roadmap, and handoff references. State when a document is a proposal or derived view rather than a canonical obligation.
